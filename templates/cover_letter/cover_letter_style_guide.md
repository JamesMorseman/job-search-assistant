# Cover Letter Style Guide

Use standard professional business-letter conventions. This guide defines
formatting and content expectations for generated cover letters.

## Document Setup

- Page size: US Letter, 8.5 in x 11 in.
- Target length: 1 page maximum.
- Margins: 0.75-1.0 in preferred. Use 0.75 in only when needed to keep a
  strong letter on one page.
- Font family: Calibri, Arial, or Times New Roman. Prefer Calibri when paired
  with the resume template.
- Font size: 10.5-11 pt preferred. Do not go below 10 pt.
- Alignment: left aligned.
- Line spacing: single.
- Paragraph spacing: modest spacing between paragraphs, typically 6-10 pt
  after each paragraph or one blank line.
- Do not use bullets unless explicitly justified by the target role or user.

## Header And Address Blocks

- Use the same candidate identity/contact information as the resume when
  available.
- Candidate header may be compact and should not dominate the page.
- Date placement: below the candidate header/contact block, left aligned.
- Employer block: company, hiring manager/recruiter if known, department if
  known, and company address/location if available.
- If the hiring manager is unknown, omit the person's name rather than inventing
  one.
- Salutation:
  - Use `Dear Hiring Manager,` when no contact is known.
  - Use a named salutation only when the name is verified.

## Body Structure

- Default body paragraph count: 3 paragraphs.
- Optional fourth paragraph only if necessary for role-specific context that
  cannot fit cleanly in three paragraphs.
- Keep paragraphs focused and compact.
- Avoid long blocks of text.
- Closing/signature:
  - Use a professional closing such as `Sincerely,`.
  - Include the candidate's full name below the closing.

## Content Rules

- Paragraph 1: name the role/company and give a concise reason for interest.
- Paragraph 2: present the strongest technical/project evidence for the target
  role.
- Paragraph 3: connect fit, communication, learning ability, and closing
  interest.
- Optional paragraph 4: use only for a necessary role-specific detail, such as
  relocation interest, unusual fit explanation, or additional project evidence.
- Do not repeat resume bullets mechanically.
- Do not paste fragment-bank text verbatim when it reads unnatural in context.
- Adapt fragments into a coherent narrative while preserving factual support.
- Do not include unsupported claims.

## Tone Rules

- Professional, direct, and specific.
- Confident but not inflated.
- Avoid exaggerated AI-style language such as sweeping claims, generic passion
  statements, or overly polished buzzword strings.
- Prefer concrete evidence over personality claims.
- Show motivation through role-specific fit and learning trajectory.
- Keep civil-engineering claims grounded in academic projects, coursework,
  verified tools, and work experience.

## Content Emphasis

- Technical/project evidence should carry the letter.
- Capstone and academic project evidence should usually outrank generic
  coursework.
- Coursework may support a point when directly relevant, but should not become
  the main evidence if a stronger project exists.
- Work experience should support coordination, documentation, training,
  scheduling, operations, field-practices awareness, or communication when
  relevant.
- Software/data automation projects may be used as evidence of automation,
  organization, testing, and workflow thinking; do not frame them as civil
  design experience.
