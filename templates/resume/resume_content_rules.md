# Resume Content Rules

Use these rules for generated resumes. The resume DOCX is a layout/style
template, not fixed content and not profile source material.

## Length Rules

- Target length: 1 page.
- Soft cap: about 1.15 pages.
- Hard cap: about 1.5 pages.
- 3 pages is never acceptable.
- Do not leave blank sections.
- If a section has no role-relevant content, omit the section.

## Summary Rules

- Professional Summary remains dynamic and must not be copied from the template.
- Summary length: 2-3 sentences.
- Summary word count: about 50-75 words maximum.
- Summary should be tailored to the target role, discipline, and strongest
  available evidence.
- Avoid generic filler and exaggerated AI-style language.

## Evidence Priority

- Engineering Experience stays front and center.
- Capstone/project evidence should outrank generic coursework.
- Strong project evidence should usually outrank non-targeted work experience.
- Preserve the strongest engineering evidence when trimming.
- Frame software/data automation projects as automation, data, and workflow
  evidence, not civil design experience.

## Coursework Rules

- Relevant Coursework is optional, not always included.
- Include coursework only when it directly supports the target role and space
  allows.
- Prefer grouped, compact coursework lists over long transcript-style lists.
- If coursework is relevant but does not fit, use it as cover-letter support
  instead.
- Do not include coursework merely to fill space if stronger project evidence
  exists.

## Technical Skills Rules

- Technical skills should be compact and grouped.
- Use short category labels such as `Software`, `Engineering`, `Construction`,
  `Analysis`, or `Documentation`.
- Include only tools and skills that are relevant to the target role or help
  explain selected project evidence.
- Do not claim direct experience with tools listed as learnable-adjacent or
  do-not-claim in the master profile.

## Work Experience Rules

- Work experience should be concise.
- Emphasize transferable leadership, scheduling, coordination, operations,
  documentation, process improvement, and training only when relevant.
- Avoid over-weighting non-engineering work if it crowds out engineering
  projects.
- Select work bullets that support the target role's collaboration, field,
  documentation, or coordination needs.

## Bullet Rules

- Prefer concise, evidence-grounded bullets.
- Start bullets with strong action verbs.
- Use metrics only when verified by the profile or other approved repository
  source.
- Do not invent outcomes, project sizes, software use, credentials, licenses,
  internships, or professional engineering responsibilities.
- Avoid mechanical repetition of cover-letter fragments.

## Trim Order When Over Length

When the resume exceeds the target length, trim in this order:

1. Remove or compress Relevant Coursework.
2. Remove weaker or non-targeted skills.
3. Reduce weaker work-experience bullets.
4. Reduce weaker project bullets.
5. Shorten Professional Summary.
6. Preserve strongest engineering evidence.

## Targeting Rules

- For structural roles, prioritize capstone structural modeling, load
  development, steel framing, foundations, serviceability, and relevant design
  coursework/projects.
- For construction/project engineer roles, prioritize construction planning,
  field-practices coursework, scheduling, safety, documentation,
  constructability, coordination, and transferable operations leadership.
- For water/site-civil roles, prioritize stormwater/cistern, hydraulics,
  surveying, transportation, and site/infrastructure coursework/projects.
- For software/data-adjacent roles or automation-heavy employers, include the
  job-search assistant project as software workflow evidence when relevant.
