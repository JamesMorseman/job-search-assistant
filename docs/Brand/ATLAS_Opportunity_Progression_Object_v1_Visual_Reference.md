**Authority:**

---

# Design Intent

The Opportunity Progression is the defining object of Pipeline.

Radar has:

```text
Opportunity Signal
```

which communicates:

```text
Detected
```

Pipeline requires an object that communicates:

```text
Moving
```

The object should immediately answer:

```text
Where is this opportunity now?

What happened recently?

What happens next?
```

without reading like:

```text
Application Record

Database Entry

CRM Object
```

The visual identity must emphasize momentum.

Not storage.

---

# Core Visual Innovation

The progression rail is not a status bar.

It is not a completion bar.

It is not a timeline.

It is:

```text
Opportunity Momentum
```

---

# Progression Rail Anatomy

Desktop v1 progression sequence:

```text
Detected
↓
Saved
↓
Reviewing
↓
Applied
↓
Interview
↓
Offer
↓
Closed
```

Internally more stages may exist.

Visually they should collapse into meaningful states.

# Emotional Outcome

A user should immediately feel:

```text
This opportunity is moving.
```

Not:

```text
This opportunity is stored.
```

Not:

```text
This is a database record.
```

Not:

```text
This is an application tracker.
```

The ideal perception is:

```text
This opportunity is progressing.

I know where it is.

I know what changed.

I know what happens next.
```

That makes the Opportunity Progression the canonical Pipeline object and the operational counterpart to Radar's Opportunity Signal.
